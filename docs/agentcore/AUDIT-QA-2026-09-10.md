### QA-01 — the QA harness is the only Python component declaring nothing

`AUDIT.md` §1 flagged this under "fix/converge deps — **no `requirements.txt`** …
an unverifiable contract," and both were then closed: `agents/fix` declares

tests, and the `pip-audit` step points only at the agent lock.

against — carries `urllib3 1.26.20`, which has five open advisories and no fix on
the 1.26 branch. The agent lock pins `urllib3 2.7.0` and is clean.

|---|---|---|---|
| PYSEC-2026-141 | 2.7.0 | Sensitive headers kept across cross-origin redirect | Low — botocore does not follow redirects on API calls |
| PYSEC-2026-1999 | 2.5.0 | Redirect/retry control confusion | Low — same reason |

### QA-02 — `auth_token_key` is unreachable, and it gates the false-PASS guard

The missing knob hardwires the auth probe to vesselAI's `localStorage["vm_token"]`.
Point the agent at any other app and `is_authenticated()` returns `False`, `run_qa`
takes the discard branch, and the run returns `error: unauthenticated` with every
finding thrown away — the guard firing correctly on a wrong premise.

This is the bug the codebase already fixed once. `main.py` carries a comment on
`--max-tokens-per-call`: *"The agent supports these and the harness could not reach
them, which made its own error message unactionable."* Same gap, different flag,
still open — and this one costs a paid browser session to discover.

**Fix:** one argument and one entry in the payload loop. Three lines.

### QA-03 — three claims about presigned-link lifetime, no cap in code

> **CORRECTION (2026-09-11).** This audit was run against `ee12159`, which was
> ten commits behind `origin/main`. Two of those commits — #86
> (`feat(harness): a content-based redactor`, `fix(harness): stop publishing
> presigned URLs to public records`) — had already landed on 2026-09-09, the day
> before. They add `agents/qa/harness/redact.py` and make the comment **name the
> S3 key instead of linking it**, with the same reasoning given below and better
> evidence: a live vesselAI artifact carrying 12 `AWSAccessKeyId` and 12
> `x-amz-security-token` values. The reviewer-facing half of this finding was
> therefore already fixed when it was written. What survives is narrower and is
> stated after the table.

`_presign()` passes `expires` straight to `ExpiresIn`. No clamp.

| Source | Claim | True? |
|---|---|---|
| `agent._presign` docstring | "Expiry is capped at the bucket's lifecycle" | No cap exists in code |
| `qa_agent/main.tf` comment | "a link cannot outlive the object it points at" | True only via the 7-day lifecycle rule |
| `--presign-expires` help | "cannot outlive [the runtime's temporary credentials] (~1 hour)" | Correct — this is the binding constraint |

The default asks for 7 days; SigV4 signed with the runtime's role session dies in
roughly an hour.

**What #86 already fixed:** the comment no longer renders `![...](url)` at all, so
there are no broken images and no credential in a public record. That was the
reviewer-facing half, and the upstream fix is better than the one proposed here —
it removes the credential at the source rather than degrading the link gracefully.

**What actually survives, and it is smaller:** the agent still calls
`generate_presigned_url` once per screenshot, and the harness now discards every
one of them in `redact.without_credentials`. That is wasted work on the paid side
of the system — an S3 API call per screenshot whose output is guaranteed to be
thrown away — plus a docstring in `_presign` still claiming a cap that has never
existed in code. Neither is urgent; both are now cheaper to fix than to keep
explaining. Reduced to **P2.6** in the plan, and its wording there is the accurate
one.

### Five edge cases

All five reproduced against the real modules with `bedrock_agentcore` stubbed the
way the repo's own tests stub it — not reasoned about.

1. **A model returns a non-string `screenshot.key`.** `schema.validate_finding`
   checks `"key" in shot` but never its type, though every sibling string field is
   type-checked. `run_qa` then evaluates `shot.get("key") in urls` against a dict.
   **Reproduced:** `TypeError: cannot use 'list' as a dict key`. `invoke()` catches
   only `SchemaError` and `KeyError`, so this escapes as a 500 — the one state that
   reaches the reviewer as "the agent crashed" rather than "the agent produced
   nonsense", which is precisely the distinction the entrypoint docstring exists to
   preserve.

2. **A model picks a screenshot label with path semantics.** `screenshot(label)`
   interpolates model-controlled text into `screenshots/{sid}/{label}.png` with no
   validation, while `_safe_report_namespace` — the sibling segment — rejects `.`,
   `..`, slashes and spaces. **Reproduced:** `label="../../reports/pr-1/latest/findings"`
   yields that key verbatim. **Not exploitable:** S3 keys are literal, so it stays
   inside the `screenshots/*` IAM scope. See QA-05.

3. **A finding's text contains markdown structure.** `_finding_block` interpolates
   `summary`, `evidence`, `expected`, `actual` and each reproduction step raw into a
   `<details>` block; the three table renderers all escape `|` and newlines.
   **Reproduced:** a summary containing `</summary></details>` closes the block early
   and everything after renders as top-level comment body. See QA-06.

4. **The target holds a connection open and the network never goes idle.**
   `wait_for_network_idle` returns only when `_inflight == 0` and nothing has moved
   for 500 ms. An SSE stream, a websocket, or a polling `setInterval` keeps
   `_last_activity` fresh forever. **Consequence:** every `navigate` and `click` burns
   the full 15 s timeout instead of ~0.5 s. See QA-07.

5. **The page under test enters a console-error loop.** `drain_events()` caps its
   *output* at 20 entries, but `console_errors` itself is unbounded between drains —
   and a drain only happens on the next read. **Measured:** 50,000 events held before
   a drain = **23.8 MB** resident, each entry already truncated to 500 chars. This is
   the "the page silently broke" case the agent exists to catch, so the shape is not
   hypothetical. See QA-08.

**Nothing breaches a threshold.** All three stop-losses sit far above measured spend,
which is the intent — they are stop-losses, not targets.

| Item | Cost | Method / verdict |

Against the caps: the corpus run recorded in `agent.py` used **18 of 62 turns** and
**137 of 600 seconds**, and `AUDIT.md` §3 records **90k–400k tokens against the
3.34 M cap**. Roughly three quarters of that 137 s run was pacing floor (17 gaps ×
6.0 s = 102 s) rather than work — at a 10 req/min quota it could not have been much
faster.

### QA-07 — a page that never goes network-idle spends half the deadline waiting

`_inflight` increments on `Network.requestWillBeSent` and decrements on
`loadingFinished`/`loadingFailed`. A long-lived connection produces the first event
and not the second, or refreshes `_last_activity` indefinitely; the loop then always
exhausts its 15 s timeout. 20 navigate/click calls: **10 s** if the page settles,
**300 s** if it never does. The only signal is one `logger.info("network did not
settle…")` per call.

**Fix:** count the settle timeouts and put the total in the findings JSON beside
`paced_seconds`, which exists for exactly this reason — "time spent waiting … is
otherwise indistinguishable from a slow agent, and the two want opposite responses."
Same argument, different clock.

### QA-04 — `_BASE_TOKENS = 2_000` understates the static prefix by ~1.9×

Measured: system prompt **13,799 chars**, tool specs **1,745 chars** — roughly
**3,885 tokens** at 4 chars/token, against the 2,000 assumed. At a conservative
4.5 chars/token it is still ~3,450.

| routes | turns | budget @ 2,000 | budget @ 3,885 | short by |
|---|---|---|---|---|
| 3 | 28 | 700,000 | 760,000 | 7.9% |
| 4 | 35 | 1,090,000 | 1,150,000 | 5.2% |
| 8 | 62 | 3,340,000 | 3,460,000 | 3.5% |

**It does not bite,** and the margin is larger than the table suggests: real runs
consume 90k–400k against the 3.34 M cap, so the ceiling is ~8× above observed spend
and a 3.5% error in it changes nothing. Recorded anyway because the function's own
docstring argues that a budget short of the run it was derived from is the bug it
exists to remove.

The tighter consequence is that the prompt-caching comment reasons from the same
"~2k tokens" figure: *"on haiku it needs the conversation to push the prefix past its
minimum."* At ~3,885 the static prefix sits just under haiku's 4,096 minimum — the
conclusion holds, with ~5% of margin rather than the 2× implied.

### QA-08 / QA-09 — recorded, not actioned

`console_errors` is bounded per entry (500 chars) and per drain (20 returned), but
the list itself is unbounded between drains: 23.8 MB at 50,000 events. A one-line cap
in `_on_event` closes it.

A CDP reply arriving after its `send()` timed out is never popped from `_pending`.
Bounded by the number of timeouts in one run — single digits — so this is tidiness,
not a leak that matters.

## 4. Security

**Strong.** The reports bucket is block-public-access with a CMK and a 7-day
lifecycle; the runtime role is scoped to two S3 prefixes and an enumerated model list
rather than `*`; the trust policy carries `aws:SourceAccount` and `aws:SourceArn`
confused-deputy conditions; the fix agent got a second role rather than two more
statements on the QA one, so a fork PR subject cannot be expressed; and #83's
backstop closes the archive leak on content rather than field names. Both findings
below are narrower than any of that.

### QA-06 — model-controlled finding text goes raw into a public PR comment

Chain: text rendered by the application under test → the model's
`summary`/`evidence`/`actual` → `_finding_block` → a comment on a public repo. The
three table renderers escape `|` and newlines; `_finding_block` escapes nothing.

**The repo has already settled this question the other way.** `agents/fix/prompt.py`
runs `sanitise()` over *the same four fields* — `summary`, `evidence`, `expected`,
`actual` — before they reach the fix model, stripping control characters and
neutralising `_FENCE_DELIMITER`. `AUDIT.md` §4 praises this as "treats finding text
as hostile input … the right architecture." One consumer of that text treats it as
hostile; the other, which publishes to a public PR, treats it as trusted.

**Reproduced:** a summary containing `</summary></details>` terminates the collapsible
block and everything after renders as top-level comment body, headings included.
GitHub's sanitiser keeps this well short of script execution, but the comment is the
product, and a finding that can restructure the report it appears in can mislead the
reviewer it is written for.

**Fix:** the escaping the table renderers already do, applied in `_finding_block`.

### QA-05 — the screenshot label is an unvalidated model-supplied path segment

Contained today: S3 keys are literal, so `screenshots/{sid}/../../reports/…` is a key
inside the `screenshots/*` prefix, not a traversal out of it, and the runtime role's
scope holds either way.

Flagged because #83 made this exact argument about the sibling segment and then wrote
the guard: *"Harmless on S3 as it stands … but the point of this guard is that its
result is safe to use as a path segment, and the day one of these is joined onto a
filesystem path that assumption is what breaks."* That applies unchanged to `label`,
which is **more** exposed — `report_namespace` comes from the harness, `label` comes
from the model.

### QA-10 — the target password lives in the model context for the whole run

The first user message is `f"Credentials: {email} / {password}"`, and the loop
re-sends the full history every turn, so the password sits inside the cached prefix
too. Inherent to an agent that must log in, and the handling around it is careful: it
is never archived, never logged, excluded from the DOM harvest (`el.type ===
'password'` is skipped), and typed through a CDP expression rather than echoed.
Recorded so the exposure is explicit — it is in every Bedrock request body for the
run, which matters if model-invocation logging is ever enabled for this account.

### Migration path

All six fixes are behaviour-preserving on the happy path; none needs a data
migration. What matters is which half they live in:

| Fix | Half | Ship via |
|---|---|---|
| QA-02, QA-06 | Harness | Merge only — the harness ships from the checkout. No package, no apply, no ARN risk. |
| QA-05, QA-07, QA-08, E1 | Agent | One `package-qa-agent.sh` → pin both values in `dev.tfvars` → `apply-dev.sh` from the main checkout. Expect `1 to change` and an `agent_runtime_version` bump; a plan proposing a replace means something else is wrong. |
| QA-01 | CI | Merge here; flag the runner-side install to vesselAI rather than editing it. |

Batch the four agent-side fixes into a single package/apply cycle. Each cycle is one
paid deploy and one ARN-comparison step, and there is no reason to spend four.

### QA-11 — the #83 backstop is the one behaviour with no runtime off-switch

`LOG_PAGE_STATE` is env-gated, `fix_agent_enabled` is Terraform-gated, every budget is
per-invoke. The credential scrub is unconditional and can only be changed by
repackaging.

The regex matches the whole serialized body, so a legitimate finding whose text quotes
a presigned URL from the page under test gets its evidence replaced with
`"[redacted credential]"` — and the `ERROR` log then says *"a field carrying a
presigned URL is not being stripped by name"*, a confident wrong diagnosis in that
case.

**Judgement: do not add a kill switch.** A flag that disables a credential scrub is a
flag someone eventually sets. Fix the log line instead — report which JSON path
matched, so a false redaction is distinguishable from a real strip-by-name hole. That
preserves the loud signal and removes the wrong diagnosis.

# Fix plan — work items, by priority

IDs continue the program's single namespace (`AUDIT.md` used P0.1–P0.3, P1.1–P1.7,
P2.1–P2.5, P3.1–P3.4; all DONE except P1.7). Severity = impact of the underlying
defect if it manifests. Priority = sequencing (cost-of-delay × effort × what it
gates).

**There is no true P0 in the "blocks release" sense** — the verdict is PROCEED and
nothing here gates a deploy. P0 below means *do first*: cheapest to ship, highest
value, and nothing downstream depends on them.

**The bands are drawn on shipping lane, not just severity**, because the two halves
cost very different amounts to land:

- **Harness / CI** — ships on merge. No package, no `dev.tfvars` pin, no apply, no
  ARN comparison. Effectively free.
- **Agent** — every change costs one `package-qa-agent.sh` → pin both values in
  `layer1_persistent/dev.tfvars` → `apply-dev.sh` from the main checkout → compare
  `terraform output qa_runtime_arn` against `gh variable get QA_RUNTIME_ARN`. One
  cycle, whether it carries one fix or six.

So **P1 is a batch, not a list** — six agent-side fixes sized to land in a single
cycle. Splitting them across cycles multiplies the only expensive step in the plan
for no benefit.

## Acceptance criteria per item

**P0.4 — QA-06.** `_finding_block` renders `summary`, `evidence`, `expected`,
`actual` and every `steps_to_reproduce` entry through the same escaping the table
renderers already apply, so a finding cannot close its own `<details>` block or
inject a heading into the comment body. Done when
`test_finding_text_cannot_close_the_details_block` passes — the direct sibling of
the existing `test_finding_text_with_a_pipe_does_not_break_the_table`. Not a new
mechanism; the same one, one function over. Do **not** reach for HTML escaping
wholesale: the block deliberately emits `<details>`/`<summary>`/`<code>` of its own,
and escaping those would break the rendering this fix is protecting.

**P0.5 — QA-02.** `--auth-token-key` exists on the parser and is forwarded when set,
so pointing the agent at a target that is not vesselAI no longer requires an agent
code change. Done when `test_every_agent_payload_key_has_a_cli_flag` passes — the
drift test matters more than the flag, because it is what stops this class of gap
recurring a third time (`--max-tokens-per-call` was the first). Introspect
`run_qa`'s `payload.get` keys against the parser's actions; same shape as the
existing `_INVOKE_DEADLINE_DEFAULT` mirror check.

**P0.6 — QA-01.** `agents/qa/harness/requirements.txt` exists, pins `boto3` and
`botocore` to versions carrying a clean `urllib3` (≥ 2.7.0 resolves every advisory
in §1), and the CI `pip-audit` step audits it alongside the agent lock. Done when a
deliberately vulnerable pin fails the job — a step that always goes green tells
nobody anything, which is the standard `ci.yml` already sets for `npm audit` and the
agent lock. **Out of repo scope:** vesselAI's runner install is what the production
harness actually resolves; flag it there rather than editing, and note in the file's
header comment that this pin is authoritative only for CI until that lands.

**P1.8 — E1.** `schema.validate_finding` requires `screenshot["key"]` to be a `str`,
matching every sibling field, so a model returning a list or dict cannot reach
`shot.get("key") in urls` and raise an uncaught `TypeError`. Done when
`test_a_non_string_screenshot_key_is_rejected` passes. Fix at the schema, not at the
presign loop: the schema is where every other field of this shape is already
checked, and a guard at the loop leaves the same value free to break the next
consumer.

**P1.9 — QA-05.** The screenshot label passes through the same one-safe-segment
guard as `report_namespace` before it becomes an S3 key, so `..`, `/` and whitespace
cannot shape the key. Contained today only because S3 keys are literal; #83 wrote
this guard for the sibling segment on exactly the argument that the containment is
incidental. Done when
`test_a_label_with_path_semantics_cannot_shape_the_key` passes. Reject-and-substitute
rather than reject-and-fail: a bad label must not cost the run its evidence.

**P1.10 — QA-07.** `wait_for_network_idle` returns whether it settled or timed out;
the session counts the timeouts and `run_qa` reports the total in the findings JSON
next to `paced_seconds`. Done when a run against a page holding a connection open
shows a non-zero count rather than only an INFO line. The rationale is already
written in the codebase for the sibling clock: *"time spent waiting … is otherwise
indistinguishable from a slow agent, and the two want opposite responses."* Same
argument, different clock. Deliberately **not** in scope: changing the 15s timeout or
the idle heuristic — measure first, then decide whether it needs tuning.

**P1.11 — QA-08.** `_on_event` stops appending past a cap, so the list cannot grow
unbounded between drains (measured 23.8 MB at 50,000 events). Done when
`test_console_errors_stop_accumulating_at_a_cap` passes; no socket needed, as the
existing CDP tests show. Keep the *count* accurate past the cap if it is cheap — the
count is what `candidates.detect` reports as evidence.

**P1.12 — QA-11.** The backstop's ERROR line names the JSON path that matched, so a
legitimate finding quoting a presigned URL from the page under test is
distinguishable from a genuine strip-by-name hole. Today both produce *"a field
carrying a presigned URL is not being stripped by name"*, which is a confident wrong
diagnosis in the first case.

**Explicitly not P1.12: do not add a kill switch for the scrub.** A flag that
disables a credential scrub is a flag someone eventually sets, and the scrub is the
control standing between a leaked STS token and a public repo — which is the leak
#77 already had. Recorded here so it is not re-proposed as an improvement.

**P1.13 — QA-04.** `_BASE_TOKENS` reflects the measured static prefix (~3,885 tokens:
13,799 chars of system prompt + 1,745 of tool specs), and a test pins the constant to
the real thing so editing the rubric cannot silently invalidate either the budget
derivation or the prompt-caching argument that shares the figure. Done when
`test_the_static_prefix_matches_the_budget_constant` passes.

**This is the one item in the P1 batch that changes a number the runtime acts on,**
so it wants its own review line rather than riding the batch unexamined. The change
is inert in practice — it raises the derived ceiling 3.5% at 8 routes, against real
runs consuming 90k–400k of a 3.34 M cap — but "inert" is a claim the reviewer should
get to check, not one the diff should bury among five guards.

**P2.6 — QA-03, reduced.** #86 already did the part that mattered: the comment
names the S3 key and `redact.py` strips the URLs, so no credential reaches a public
record and no reviewer sees a broken image. What is left is that the agent still
generates presigned URLs the harness is now guaranteed to discard — an S3 API call
per screenshot whose output cannot survive — and a `_presign` docstring claiming a
cap that has never existed in code.

**Not scheduled on its own.** It is agent-side, so it costs a deploy cycle, and it
buys a few API calls and an accurate comment. Fold it into the P1 batch if that PR
is still open when this is read; otherwise leave it for the next cycle that happens
anyway. Recorded rather than done, because the reasoning for *not* doing it now is
the useful part.

**P3.5 — QA-09.** Not scheduled. The timeout path leaves `msg_id` in `_pending`, so a
late reply is retained for the life of the session — bounded by the number of
timeouts in one run, which is single digits. Real, harmless, and cheaper to leave
recorded than to spend a deploy cycle on. Fold it into the next agent cycle that
happens for another reason.

**P3.6 — QA-10.** No action planned, and that is the finding. The target password is
in the first user message and therefore in the cached prefix for the run's duration;
this is inherent to an agent that must log in, and the handling around it is already
careful (never archived, never logged, excluded from the DOM harvest, typed through
CDP rather than echoed). Recorded so the exposure is explicit rather than assumed
absent. **Reopening condition:** if Bedrock model-invocation logging is ever enabled
for this account, the password lands in a durable log and this becomes a real item.

## Suggested sequence

1. **P0.4 → P0.5 → P0.6 as one PR.** All harness/CI, all merge-only, no deploy
   surface. QA-06 first: it is the only item touching what gets published to a public
   repo, and it is three lines plus a test.
2. **P1.8 → P1.13 as one PR and one package/apply cycle.** Package once, pin both
   values into `dev.tfvars` in the same commit, apply from the main checkout. Expect
   the plan to read `0 to add, 1 to change, 0 to destroy` with `agent_runtime_version`
   incrementing and the ARN holding; a plan proposing a *replace* or *destroy* means
   something other than this change is in it — stop and read it before applying.
   Compare `terraform output qa_runtime_arn` against
   `gh variable get QA_RUNTIME_ARN --repo amdhd/vesselAI` and set it **only if they
   differ**.
3. **P2.6 folds into step 2 if that PR is still open**, since it is agent-side after
   the correction. Otherwise it waits for the next cycle. It does not justify one.
4. **P3.5 rides the next agent cycle** that happens for some other reason. P3.6 is
   recorded, not scheduled.

Total: **two PRs and one paid deploy** to close every actionable finding in this
audit.
